How We Prove Quality Parity

Three methodologies, different tradeoffs. Run Approach 3 first (fastest), then Approach 2 (historical validation), then Approach 1 only if needed.

Approach 3 · Fastest
Rule Engine Audit vs ALTA Standard Exceptions
Map each of our 24 title_rules to a corresponding ALTA Standard Exception code (ACCX01, DTSX10, CONX02, etc.). Gap analysis: what ALTA codes don't we cover? Add rules until coverage ≥ 85-90% of codes relevant to distressed/investor use cases. Skip fresh-closing-only codes honestly.
1 day · SUMMIT
Approach 2 · Uses existing data
Historical Validation Against Known Outcomes
Use 200 resolved auctions from 2023-2025 where outcomes are known (foreclosure_outcomes + tax_deed_outcomes tables already exist). Run our title pipeline against pre-auction state, score whether we'd have flagged the actual title issues that emerged. Target: ≥ 85% precision, ≥ 80% recall.
3 days · Post-pilot
Approach 1 · Gold standard
Blind Panel vs Traditional Abstractor
50 Brevard foreclosure properties, comparison panel: our pipeline vs paid traditional title abstractor ($75-150/search) vs Dono's published 32-data-points claim. Score on 7 investor elements. Target: accuracy ≥ 90% vs abstractor baseline. If 85-89% we caveat; if <85% we pull the claim.
2 weeks · Only if needed
