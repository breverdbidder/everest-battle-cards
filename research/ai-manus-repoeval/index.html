Layer 2 · Backend Infrastructure
MongoDB + Redis + Beanie + FastAPI — DO NOT FORK
Adopt: NO

Forking the backend means rebuilding the data plane against a fundamentally different database. High risk, no upside.

✓ What We Take From It
DDD layering pattern (domain / application / infrastructure / interfaces) as architectural reference for any new Python service. Zero code, one architectural discipline lesson.
03
Layer 3 · Sandbox Isolation Model
Per-task Docker + Xvfb + x11vnc + noVNC
Adopt: REFERENCE

2,926 LOC. Each task gets an ephemeral Ubuntu 22.04 container with supervisord managing Chrome (CDP :9222) + Xvfb + x11vnc (:5900) + FastAPI (:8080). Backend creates per-task via mounted /var/run/docker.sock. noVNC RFB client streams live browser to the Vue frontend via WebSocket proxy.

✓ What We Take From It
Architectural template for any future BidDeed/ZoneWise sandboxed agent that needs a live browser view (Phase 2 Playwright capture, for example). Currently the CI PROTOCOL assumes Firecrawl browser_execute OR local Playwright — adding a Hetzner-hosted per-task sandbox is a parallel option if Firecrawl credits become the constraint. Reference only until that constraint bites.
04
Layer 4 · Agent Loop + System Prompt
PlanActFlow state machine + 10-section prompt — ADOPT
Adopt: YES

171 LOC state machine at backend/app/domain/services/flows/plan_act.py. 6-state enum (IDLE / PLANNING / EXECUTING / UPDATING / SUMMARIZING / COMPLETED). Dual-agent separation: PlannerAgent with tool_choice: "none" + format: "json_object", ExecutionAgent handles all tool calls. compact_memory() called after every step before UPDATING — this is the KV-cache discipline from the Manus architecture notes. 10-section XML-tagged system prompt at domain/services/prompts/system.py with verbatim <important_notes> that reads "You must execute the task, not the user. Don't deliver the todo list, advice or plan to user, deliver the final result to user." — identical to the NEVER-HAND-BACK rule in our CLAUDE.md.

✓ What We Take From It (4 Concrete Extracts)
Extract #1 — 6-state PlanActFlow enum → Hermes-agent (SUMMIT #119). Our current Hermes has trajectories but no UPDATING state; planner never re-plans after step result. Regression vs Manus. Port enum + transition logic. ~2 hrs.

Extract #2 — compact_memory() per-step → AUTOLOOP V2 evolver. Our fail→RCA→evolver loop has no memory compaction; retries grow unbounded. Adding compaction between evolver iterations should cut retry token cost. ~3 hrs. UNTESTED estimate.

Extract #3 — dual-agent planner/executor separation → SUMMIT worker. Current SUMMIT worker blends planning + execution in a single Claude Code session; risks goal drift after 50+ tool calls. Restructure one pilot SUMMIT. ~4 hrs.

Extract #4 — 8-event taxonomy (Plan / Step / Tool / Message / Title / Done / Wait / Error) → zonewise-web/app/chat-v2/client.tsx dispatcher. Currently chat-v2 emits raw text chunks + ad-hoc onArtifactUpdate. Adopting the Manus taxonomy lets existing components/tool-ui/* primitives dispatch cleanly on event type. Part of Track A queue.

KV-cache compaction between evolver iterations · P0 · ~3 hrs
